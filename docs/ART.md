# Contributing art to Hive Legends

All in-game art is programmer art generated by code (`src/game/textures.ts`).
Real drawn art replaces it **without touching any code**: drop a PNG into
`public/art/`, list it in the manifest, refresh. This document is the
contract.

## The one hard rule: originality

Every asset must be **original work**. Gauntlet Legends (and any other game)
may inspire mechanics and structure only — never reproduce its characters,
sprites, tiles, maps, logos, or other protected expression, and no
AI-regurgitated or traced copies of existing game art. The game's identity is
**hive fantasy**: chitin, resin, spores, amber and violet bioluminescence
against dark warrens (see `docs/design/visual-direction.md` for the style
pillars and palette anchors).

## How to ship an override

1. Draw your PNG at the **exact canvas size** listed below (transparent
   background).
2. Save it as `public/art/<texture-key>.png` — the filename *is* the texture
   key, e.g. `public/art/tile-floor-0.png`.
3. Add the key to `public/art/manifest.json`:
   ```json
   ["tile-floor-0", "hero-vanguard-2-w0"]
   ```
4. `npm run dev` → your art is live. Any key not listed/present falls back to
   generated art, so partial packs are fine.

Wrong-sized files are rejected at boot with a console warning (generated art
is used instead), so a bad export can't silently break the game. Listing a
key with no matching file logs a browser 404 — keep the manifest in sync.

## Texture keys and sizes

The machine-readable source of truth is `src/game/textureSpecs.ts`; the
tables below summarize it.

### Tiles (top-down; must tile seamlessly)

| Key | Size | Notes |
| --- | --- | --- |
| `tile-wall` | 32×32 | Wall "roof" slab (edge walls) |
| `tile-wall-inner` | 32×32 | Flat variant for fully surrounded walls |
| `tile-wall-face` | 32×16 | South-facing front face (fake height) |
| `tile-floor-0`…`tile-floor-3` | 32×32 | Variants: mottle / cracks / membrane / bone scatter |

### Heroes (36×36 per frame)

Keys: `hero-vanguard-<dir>-<pose>` where `dir` is 0–7 (0 = east, clockwise:
1 = SE, 2 = south, 3 = SW, 4 = west, 5 = NW, 6 = north, 7 = NE) and `pose`
is `w0`/`w1` (walk cycle) or `atk` (attack swing). `hero-vanguard` (no
suffix) is the menu portrait — usually a copy of `2-w0`.

Do **not** bake in the player accent color, shadows, or the facing chevron —
the renderer draws those. Keep the silhouette readable at 1× game scale.

### Enemies (drawn facing +x; the renderer rotates them)

Keys: `enemy-<family>-<tier>-<frame>` — frames `w0`/`w1` (crawl cycle) and
`windup` (attack telegraph — must read as clearly different).

| Family | Size | Silhouette |
| --- | --- | --- |
| `skitter` | 24×24 | Small round swarmer |
| `husk` | 32×32 | Broad lumbering bruiser |
| `spitter` | 28×24 | Thin body, bulbous rear sac, funnel mouth |

Tier palettes (family shape stays identical): `common` pale spore-green,
`veteran` amber, `elite` crimson **with a glow outline**. Palette hex anchors
live in `docs/design/visual-direction.md`. Readability beats richness: a
15-enemy horde must parse at a glance by silhouette + palette alone.

### World objects

| Key | Size | Notes |
| --- | --- | --- |
| `generator-brood-node-0/1/2` | 44×44 | Damage tiers: intact / cracked-leaking / crumbling with exposed core |
| `prop-resin-husk`, `prop-amber-clutch` | 20×20 | Breakables; shadow may be baked (renderer draws none for props) |
| `pickup-gold` | 16×16 | `pickup-health` 18×18 |
| `exit-portal` | 48×48 | Renderer spins/pulses it; design for rotation |
| `decor-egg-cluster` | 24×20 | `decor-resin-web` 28×28, `decor-spore-patch` 24×18 |

### Effects (usually fine as generated; tintable = draw in white)

`fx-shadow` 32×14 · `fx-accent-ring` 40×40 (white, tinted per player) ·
`fx-chevron` 14×14 (white, points +x) · `fx-glow` 48×48 (white radial) ·
`fx-bolt` 12×6 (white capsule, points +x) · `fx-mote` 4×4 · particles:
`fx-ichor` 6×6, `fx-shard` 8×8, `fx-spark` 6×6, `fx-dust` 8×8, `fx-heart` 7×7.

## Lighting and shadows

Don't bake lighting, vignettes, or drop shadows into sprites (props are the
one exception, noted above) — the renderer layers glows, shadows, and the
vignette itself. Floors should stay noticeably darker than characters
(roughly 3×) so actors pop.

## Checking your work

`npm run dev` for the live view. The full gate before a PR:

```bash
npm run lint && npm run typecheck && npm test && npm run build && npm run test:e2e
```

See `docs/TESTING.md`. Screenshots of your art in a live horde are the
review currency — include them in the PR.
